# Правила роботи над проєктом

Розробка ведеться з кількох комп'ютерів. Єдине джерело правди — цей репозиторій.
Усе, що потрібно для продовження роботи, має бути в `docs/`, а не в пам'яті,
локальних нотатках чи історії чату.

## 1. Початок сесії

1. `git pull`.
2. Прочитати [status.md](status.md): що зроблено, що в роботі, наступні кроки.
3. Якщо задача пов'язана з активним планом — прочитати його в [plans/](plans/).

## 2. Під час роботи

- **Рішення** (вибір стеку, архітектури, бібліотеки, підходу) фіксуються як ADR
  у [decisions/](decisions/) за шаблоном [decisions/_template.md](decisions/_template.md).
  Нумерація наскрізна: `0001-short-name.md`, `0002-...`.
- **Плани** (кроки реалізації фічі чи етапу) — у [plans/](plans/), один файл на план.
  Хід виконання відмічається прямо в плані чекбоксами.
- **Відкриті питання та ідеї**, які не вирішені зараз, — у розділ «Відкриті питання»
  в [status.md](status.md), щоб не загубились.
- Якщо рішення змінює попереднє — не редагувати старий ADR по суті, а створити новий
  і позначити старий як `Замінено ADR-XXXX`.

## 3. Кінець сесії (обов'язково)

1. Оновити [status.md](status.md): що зроблено, на чому зупинились, наступні кроки.
2. Оновити індекс [README.md](README.md), якщо з'явились нові документи.
3. Закомітити й запушити — незакомічена робота на іншому ПК недоступна.

## 4. Git

- Основна гілка — `main`.
- Повідомлення комітів у стилі Conventional Commits англійською:
  `feat:`, `fix:`, `docs:`, `chore:`, `refactor:`, `test:`.
- Не залишати незакомічені зміни між сесіями.

## 5. Мова

- Документація — українською.
- Код, ідентифікатори, коментарі в коді, коміти — англійською.
- Інтерфейс продукту — кілька мов, див. розділ 6.

## 6. Інтерфейс і мови

- Інтерфейс мультимовний (зараз `en`, `uk`) — див. [ADR-0006](decisions/0006-i18n.md).
- Жодних текстів, зашитих у компоненти: тільки через ключі в `apps/web/messages/`.
- Додаючи чи змінюючи текст — оновлювати всі мовні файли в тому ж коміті.

- Шапка й футер сайту (`apps/site`) і застосунку (`apps/web`, `AppShell`) — ідентичні:
  лого + «Adelie» зліва, перемикач теми справа; у футері посилання зліва, мови справа.
  Стилі дзеркальні: `apps/site/style.css` ↔ `.shell-*` у `apps/web/src/app/globals.css` — змінювати разом.
- Дві теми (світла/темна), за замовчуванням — системна. Назва продукту — завжди «Adelie».

## 7. Зміна правил

Ці правила можна змінювати — так само через коміт із поясненням причини.
