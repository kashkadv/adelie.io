**Напрями сцен (власник, 2026-11-26)**

- [x] У даних і «Правилах» — загальна схема: **напрям** локації (Інтер'єр / Студія / Природа) → **тип сцени** (вітальня,
      спальня… / подіум, паперовий фон, на столі, вигляд згори… / тераса, ганок…) → свої правила й свій макет; «кімната»
      стає окремим випадком типу сцени. Місце виробу задає тип сцени: підлога, стіна, поверхня, вигляд згори.
- [ ] Наповнюємо спершу «Інтер'єр»; далі **Студія: подушки й пуфи на подіумі** (перший запит власника). Це об'ємні вироби:
      фото виробу спереду / на ¾ на рівні очей, макет — подіум і безшовний фон, камера на рівні виробу, контактна тінь
      на подіумі; рецепт «виріб на поверхні» окремо від плаского «виріб на підлозі». Вигляд згори (flat lay) для
      ліжників і килимів — найпростіший для нашого рецепта, кандидат наступним.
- [x] Поле локації «Завжди в цій локації» (1–3 обов'язкові речі, напр. «панорамне вікно»); у промпті — одразу після
      стилю.

**Зроблено 2026-11-26 (власник):** живий прогрес (кроки з ComfyUI, етапи, час, заглушки під сцени, що генеруються);
«Уточнити» — ПК редагує одну сцену за інструкцією (FLUX 3 Klein, сцена як image 1), решта лишається; результати — нові
сцени («Уточнення №N»). Перевірено на ПК: шале — балки, обшивка, камін, вечір; уточнення «прибери торшер, картина над
диваном» — змінилось лише це. Перетягування локацій і порівняння двох поруч — пізніше. Стіни вільні для моделі — не
знадобилось: стиль першим у промпті дав балки й обшивку.

**Референси (2026-11-26).** До 3 фото в «Додати сцени». Перевірено на ПК з фото власника: картинка як референс
давала слабкий вплив або копіювала розташування референса замість макета; **опис словами** (FLUX 3 Klein prompt upsampler,
Qwen3.5-9B w4a8, ≈ 4–6 хв на фото, у 8 ГБ не вміщається повністю) передав стиль точно й зберіг макет. Тому референс іде в
генерацію лише як слова; опис зберігається на файлі (`asset.recipe.description`) і повторно не рахується. Qwen3-VL-4B
(енкодер FLUX 3) текст не генерує — як описувач не підходить.

**Скетчі й фото-якість (власник, 2026-11-27).** Тести на 5 скетчах власника (олівець, контури, кольоровий): скетч дає
кімнату значно кращу за макет з брусків (архітектура, вікна, деталі). Мальованість: олівцеву штриховку розмивати перед
генерацією; найкраще — контурний скетч. Фото-якість: порівняння (а) як було, (б) Klein Base 50 кроків (~7 хв — надто
повільно), (в) ~2 Мп, (г) прохід RealVisXL V5.0 (OpenRAIL++, комерційне дозволено) — власник обрав **(в)+(г)**. Тепер:
скетчі в локації (тип сцени; ПК сам визначає олівець/контури/кольоровий), «Додати сцени» зі скетчем або макетом, усі сцени
~2 Мп + фінальний прохід RealVisXL (сила 0,3), ≈ 3 хв на сцену. Правило: пледи й овчини лише на диванах і кріслах. Зону
виробу на скетчі позначаємо на кроці «Виріб у сцені».
