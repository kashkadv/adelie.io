# Обговорення: інфраструктура на домашньому Proxmox

- **Статус:** частково реалізовано — VM створено, див. [infra/server-setup.md](../infra/server-setup.md)
- **Створено:** 2026-11-05

У власника проєкту є домашній міні-сервер на Proxmox, де можна створювати
контейнери/VM під Adelie.

## Що це дає

1. **Спільне dev-середовище для двох ПК.** PostgreSQL і Redis на сервері →
   з обох ПК працюємо з тими самими даними (підключені акаунти, накопичені snapshots).
   Із локальним Docker Compose на кожному ПК дані розходились би.
2. **Ранній збір історії.** Worker на сервері може щодня синхронізувати Pinterest
   Gushka вже з етапу 2 — історія метрик накопичується, поки ми пишемо UI.
   Це цінно: історію до підключення API може не віддати (ТЗ 6.4).
3. **Можливий staging / перший production для Gushka** (етап 4) — без витрат на хостинг.

## Варіант організації (пропозиція)

- Одна VM (Debian/Ubuntu) з Docker → docker compose: postgres, redis,
  пізніше api + worker + web. VM надійніше для Docker, ніж LXC.
- Доступ з ПК — через Tailscale (або LAN, якщо обидва ПК вдома).
- `docker-compose.yml` у репо працює і локально, і на сервері — можна
  запускати все на ПК, якщо сервер недоступний.
- Бекапи: Proxmox backup VM + `pg_dump` за розкладом.

## Що треба врахувати

- **Публічний доступ і OAuth.** Для production-callback'ів платформ і для
  Gushka потрібен HTTPS-домен. Варіанти: Cloudflare Tunnel (без відкриття портів),
  reverse proxy з Let's Encrypt. Для dev OAuth, можливо, вистачить localhost — перевірити на етапі 0.
- **Надійність production вдома:** світло, інтернет, домашній IP. Для MVP з одним
  клієнтом прийнятно; для платних клієнтів — переглянути.
- **Безпека:** токени соцмереж зберігаються зашифровано; сервер не відкривати
  назовні напряму.

## Відкриті питання

1. ~~Де ПК? VPN?~~ Див. відповіді — Tailscale.
2. ~~Ресурси?~~ VM: 4 vCPU, 4 GB RAM, 60 GB (RAM хоста обмежена).
3. ~~Домен і DNS?~~ `adelie.space`, DNS переносимо на Cloudflare.
4. ~~Хто налаштовує VM?~~ Через SSH, VM створено, налаштування через SSH — [infra/server-setup.md](../infra/server-setup.md).
5. Використовуємо сервер лише для dev, чи одразу плануємо його як production для Gushka?

## Відповіді

- **Домен:** `adelie.space` — власний домен продукту (придбано 2026-11-05).
  Спочатку розглядався `uamade.xyz`, але його замінено.
- **Машини:** міні-ПК (Proxmox, сервер) і стаціонарний ПК — вдома;
  ноутбук — будь-де. Отже, LAN недостатньо: ноутбуку потрібен доступ ззовні
  до dev-БД. Пропозиція — Tailscale (приватна мережа між пристроями, БД не
  відкривається в інтернет; персональний план безкоштовний — перевірити ліміти).
- **Приватна мережа:** Tailscale (2026-11-05). Сервер, стаціонарний ПК і ноутбук
  у спільній tailnet; dev-БД і Redis доступні лише через неї.

### Пропозиція схеми піддоменів `adelie.space` (чекає підтвердження)

- `adelie.space` — лендінг / маркетинговий сайт (пізніше).
- `app.adelie.space` — веб-застосунок.
- `api.adelie.space` — API та OAuth callback'и платформ.
- `staging.` / `dev.` — за потреби, для тестових середовищ.

- **DNS:** `adelie.space` на Cloudflare — активовано 2026-11-05. Публічний доступ
  до сервера — через Cloudflare Tunnel (без відкриття портів на роутері).

### Інструкція: перенесення DNS на Cloudflare (виконує власник)

1. Зареєструватись / увійти на dash.cloudflare.com → «Add a domain» → `adelie.space`.
2. Обрати безкоштовний план (Free).
3. Cloudflare покаже 2 nameservers — прописати їх у реєстратора домену
   замість поточних (налаштування NS / DNS-сервери).
4. Дочекатись активації (від хвилин до ~24 год) — Cloudflare надішле лист.
5. DNS-записи поки не створюємо — їх додасть Cloudflare Tunnel пізніше.
- **Доступ:** власник надав root SSH до хоста Proxmox; VM створено автоматично
  (cloud-init). Працюємо лише з VM 104 `adelie`, інше на хості не чіпаємо. Інструкція: [infra/server-setup.md](../infra/server-setup.md).
