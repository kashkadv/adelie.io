# План: Майстерня публікацій

**Статус:** план (2026-11-24), код не почато. Рішення: [ADR-0040](../decisions/0040-publication-workshop.md),
[ADR-0041](../decisions/0041-gpu-worker-on-demand.md). Пов'язані: [content-calendar.md](content-calendar.md),
[link-builder.md](link-builder.md), [infra/local-llm.md](../infra/local-llm.md).

## Етап 0 — перевірка якості на ПК (власник, години)

- [ ] Встановити ComfyUI на ПК; вручну пройти конвеєр на 3–5 фото Gushka: вирізання (BiRefNet), новий фон (SDXL inpaint),
  апскейл (Real-ESRGAN), прибирання виробу (LaMa).
- [ ] Спробувати FLUX.1 Kontext (GGUF Q4) на 8 ГБ: час і якість.
- [ ] Рішення: які воркфлоу беремо; зафіксувати в `infra/gpu-agent/workflows/`.

**Результати перевірки (2026-11-25, ПК власника: RTX 3060 Ti, ComfyUI 0.46 у `~/ComfyUI`, PyTorch 2.11 cu128; вільно ≈ 6,5 ГБ
VRAM, бо ≈ 1,5 ГБ займає робочий стіл):**

- Апскейл Real-ESRGAN x4plus (ComfyUI, ядро, без custom nodes): 540×800 → 2160×3200 за ≈ 5 с. Контури й візерунок чіткіші, але
  вовняна фактура стає «намальованою» (ворсинки зникають). Для візерунків і тексту — добре, для вовни — лише з обережним
  змішуванням з оригіналом або іншою моделлю.
- Вирізання BiRefNet (`birefnet-general`, ONNX через rembg, CPU ≈ 11 с/фото): краї ворсу й хутра зберігаються дуже добре,
  але вирізається найвиразніший об'єкт цілком (подушка — разом зі стільцем, куртка — разом з моделлю й сумкою), а не
  «товар». Для фото в інтер'єрі й на моделі потрібне сегментування за підказкою (SAM2 + Grounding) або фото на нейтральному
  фоні. BiRefNet — для чистих предметних фото.
- custom node `ComfyUI-RMBG` не ставили: тягне groundingdino, SAM і протобуф з жорсткою версією — ризик для спільного
  оточення; сегментування за підказкою перевіряти окремо.
- PyTorch cu128 → ComfyUI радить cu130+ для оптимізованих операцій (драйвер 580 підтримує CUDA 13); для SDXL/FLUX
  спробувати оновлення.
- **Уточнення за відгуком власника (2026-11-25):** (1) апскейл губить вовну — залишаємо лише запасним для фото < ≈ 1000 px:
  ×4 → зменшити до ×2 і змішати 50/50 з простим збільшенням оригіналу; за замовчуванням не застосовувати (оригінали Etsy
  ≈ 2000×3000, піну досить 1000×1500). (2) «Тінь» навколо подушки — ореол з кольору старої стіни на напівпрозорих краях:
  виправляє відновлення кольору переднього плану (`pymatting.estimate_foreground_ml`) — у конвеєр; alpha matting
  (rembg) гірший (блокові артефакти, втрата тонких пасом) — не брати. Світлі плями між пасмами — помилка маски, а не колір
  (стіна крізь ворс вважається виробом): ховаються світлим теплим новим фоном; для чистого вирізання брати фото на
  однотонному фоні.
- **Оцінка власника (2026-11-25):** вирізання з відновленням кольору + маска, стиснута на ≈ 1 px — «гарно» (основний
  варіант); апскейл ×4 → ×2 із змішуванням 50/50 — «дуже добре»; alpha matting — теж «гарно», але лишаються невирізані
  проміжки між пасмами (є в усіх варіантах). **Головна відкрита проблема:** прогалини між ворсом, де видно стіну.
  Ідея для перевірки: вибрати колір старого фону біля краю маски й зробити прозорими пікселі всередині маски, близькі до
  нього (світлі, малонасичені), з м'яким порогом — лише в замкнутих кишенях.
- **Прогалини між пасмами (2026-11-25):** колір стіни береться з кільця навколо маски (медіана в Lab; для p2 L 78, a −1.6,
  b 0.3, вовна — b ≈ 13), піксель усередині маски стає прозорим за відстанню до нього: повністю прозорий нижче 3, зберігається
  вище 7 (м'яко, + розмиття 0.7 px), далі відновлення кольору й стиснення маски на 1 px. Поріг 5–11 надто агресивний (білі
  волосини «пересвічуються»); 3–7 — кращий баланс, але найсвітліші волосини блідішають і подекуди з'являються «намистинки».
  Працює для ворсистих речей на світлому нейтральному фоні; для інших фонів колір стіни інший, поріг підбирати.
- **Підбір очищення прогалин (2026-11-25, p2; тест на червоному фоні):** на світлому кремовому фоні здавалось, що найкраще
  змішування 50/50 маски 3–7 з «до» (D), але на **червоному** фоні кольоровий ключ по пікселях робить у вовні дрібні дірки
  («червоні крапки») — D, C, B відкинуто. Основний варіант — **E: прозорими стають лише закриті кишені стіни** (зв'язні
  області пікселів, близьких до кольору стіни, площею ≥ 60 px, поріг відстані Lab < 6, межа розмита 0.8 px; з видалених
  уцілілі «крапки» залишаються). Без дірок у вовні, кишені чисто прибрані на обох фонах. Недоліки: краї кишень різкі
  («блобові»), особливо вгорі, де їх багато; верхній лівий край маски BiRefNet кутастий. Безпечний варіант за замовчуванням
  — без очищення (A). Колір стіни береться з кільця навколо маски, тож параметри підбирати для кожного типу фону.
  Тестувати нові кроки конвеєра обов'язково на кількох фонах, зокрема насичених і темних, а не лише на світлому.
- [ ] Не перевірено: новий фон (SDXL, виріб поверх згенерованої сцени), прибирання виробу (LaMa), FLUX.1 Kontext GGUF,
  BiRefNet на GPU, сегментування за підказкою.

## Етап 1 — майстерня без GPU

- [ ] Figma: токен у налаштуваннях проєкту (зашифрований); «Синхронізувати з Figma»; таблиця шаблонів (канал, розмір,
  слоти `#photo/#title/#logo/#badge`).
- [ ] Формат шаблону (дерево шарів, ролі слотів) — спільний для Figma й власних файлів; папка шаблонів у репозиторії.
- [ ] AI-чернетки шаблонів у цьому форматі (5–8 варіантів за токенами ADR-0009) і прев'ю в Adelie.
- [ ] (За бажанням власника) підключити конектор Figma в claude.ai й перевірити, що він уміє створювати.
- [ ] Рендерер Satori + resvg на сервері; self-hosted шрифти; PNG 1000×1500 і 1080×1350.
- [ ] Том для файлів на HDD сервера (Proxmox → VM `adelie`, `/srv/adelie-assets`); щоденна копія оригіналів на другий диск; оригінали власних завантажень у R2; SMART-моніторинг.
- [ ] Бібліотека файлів: таблиця `asset` (походження, роль, хеш, мітки, батьківський файл, рецепт), мініатюри, віддача через API; завантаження перетягуванням.
- [ ] Ручне видалення: варіант чи референс одним кліком, «Очистити зараз» для запису; файл з іншими посиланнями лишається.
- [ ] Очищення: невибрані варіанти через 24 години після публікації (7 днів — без публікації), кешовані референси без посилань, «Залишити», лічильник посилань, показ звільненого місця.
- [ ] Модель: візуали й текст каналу в записі календаря (міграція), зберігання зображень.
- [ ] Інтерфейс «Створити» в картці запису: старт з ідеї/товару (фото з каталогу) / порожньо; вибір шаблону й кадрування.
- [ ] AI-текст каналу: Pinterest (назва, опис, теги, alt), Instagram (підпис, хештеги); ліміти; редагування.
- [ ] Мічене `go.`-посилання з Link Builder в тексті.
- [ ] Видача: PNG, копіювання текстів, «Відкрити створення піна», дата в календар.
- [ ] «Копія на інший канал».
- [ ] Пакетні дії: підготовка збірок для запланованих записів тижня, серія за шаблоном, перегляд сіткою.

## Етап 2 — GPU-воркер

- [ ] `gpu_worker`, `gpu_job`, ендпоінти heartbeat і claim; ключ воркера.
- [ ] Агент на ПК (`infra/gpu-agent`): heartbeat, перемикач «Дозволити Adelie GPU», перевірка VRAM, запуск воркфлоу ComfyUI.
- [ ] Індикатор стану ПК; черга «чекає на ПК»; Wake-on-LAN (за потреби).
- [ ] Дії в майстерні: апскейл, вирізання, новий фон, прибрати виріб; варіанти й вибір кращого.

## Етап 3 — рубрика «З Гушкою / без Гушки»

- [ ] Пара кадрів (з виробом / без), шаблони рубрики, швидке створення двох записів.

## Відкриті питання

- Імпорт з Google Диска (Picker, доступ лише до вибраних файлів): окремим кроком після етапу 1; потрібен OAuth-клієнт Google (поки застосунок у режимі «Testing», токен оновлення живе 7 днів — перевірити).
- Мудборд проєкту — повернутись після етапу 1.
- Ліміти Figma API на тарифі власника.
- Чи знадобиться запасний хмарний шлях для зображень.
