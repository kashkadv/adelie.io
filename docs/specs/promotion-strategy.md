# План просування (Promotion Strategy)

**Статус:** чернетка специфікації (2026-11-11), чекає підтвердження власника.
**Пов'язані:** [specs/tracker.md](tracker.md) (Flipper, Link Builder), [specs/pebble.md](pebble.md) (дослідження ринку),
[ADR-0024](../decisions/0024-promotion-strategy-module.md).

## 1. Навіщо

Власник має два бізнеси: **Gushka** (вироби, Etsy/сайти) і **мод для ETS2/ATS** (безкоштовний, донати «якщо сподобався»,
поки без каналів і аудиторії). Окрім аналітики, потрібна допомога **вирішувати, що публікувати й коли**. Adelie має
вести цикл: ціль → план → публікації → вимірювання → корекція, де кожна порада спирається на дані й пояснюється.

## 2. Вхідні обмеження (відповіді власника, 2026-11-11)

- Що потрібно від «стратегії»: **календар публікацій і поради, що саме публікувати**.
- Ресурс: **1–2 години щодня** (≈ 7–14 год/тиждень) — план має бути реалістичним за часом, завдання мірятися в хвилинах.
- Ціль для моду: **завантаження**; відповідно є конверсія (відвідувач → перехід на завантаження).
- Допускається AI-генерація тексту з перевіркою людиною; **постачальник — OpenAI** (за ADR-0024 — за
  абстракцією, щоб його можна було замінити).
- Мод особистий: один користувач, без команди.

## 3. Цикл

1. **Бриф проєкту:** що це, для кого, мова аудиторії, що вже є (відео, скріншоти, сторінка завантаження), години на день.
2. **Ціль:** метрика, значення, термін. Для моду: «N переходів на завантаження за 90 днів» (+ ручний ввід справжніх
   завантажень/підписок, поки немає API джерела). Конверсія = переходи на завантаження ÷ відвідувачі лендінгу.
3. **Стратегія (чернетка від AI, редагує людина):** канали (YouTube, Shorts/TikTok, Reddit, Discord…), **стовпи контенту**
   (огляд, процес, порівняння, поради гравцям), **ритм** під бюджет часу, **гіпотези** (кожна з метрикою й терміном перевірки).
4. **Календар:** записи «дата · канал · формат · тема/ідея · гачок · чернетка підпису · теги · заклик до дії ·
   відстежуване посилання (Link Builder) · оцінка часу · статус» (ідея → чернетка → готово → опубліковано → виміряно).
5. **Вимірювання:** Flipper (відвідувачі, джерела за UTM, `OutboundClick` на завантаження/донат) + статистика платформ,
   коли їх підключено. Порівняння з ціллю.
6. **Щотижневий огляд:** що спрацювало за каналом/форматом/темою, що змінити; AI формулює висновок **лише з наявних
   цифр**, показує докази, пропонує коригування календаря.

## 4. Поради «що публікувати»

- Генерація: бриф + опис моду + активна стратегія + результати минулих публікацій → список ідей з **обґрунтуванням**
  («чому цей формат: …») і позначкою якості доказу: **гіпотеза** (немає даних), **за даними ринку**, **за вашими
  результатами**. Без даних Adelie чесно каже, що це гіпотеза.
- Ідеї підганяються під час: 1–2 год/день ≈ 3 короткі відео + 1 довге на тиждень як стартова пропозиція, не жорстке правило.
- Користувач приймає, змінює або відхиляє; відхилене й прийняте враховується в наступних порадах.

## 4.1. Поради щодо назв, тегів і описів (додано 2026-11-11, запит власника)

Окрема частина порад — **метадані, що допомагають знаходженню**: назва, опис, теги/хештеги, обкладинка-текст, перший
рядок опису, закріплений коментар. Для кожної публікації календаря й для самого моду (сторінка Workshop/Nexus, лендінг):

- **Варіанти назви** (2–3) з коротким поясненням (ключове слово на початку, довжина під межі платформи, гачок);
- **Опис** за шаблоном платформи: перший рядок до «показати більше», ключові слова природно, посилання з UTM, заклик до дії;
- **Теги/хештеги:** набір під ліміти платформи (YouTube — теги й опис, Shorts/TikTok — хештеги, Workshop — теги);
  основа — слова з реальних джерел (пошукові підказки, схожі моди, тренди), а не вигадані; позначка якості доказу;
- **Перевірки без AI** (детерміновано): довжина, ліміти, дублі, відсутність ключового слова, застарілі/заборонені
  хештеги, відповідність мови аудиторії; результат як у «Проблем товарів» (критичне / важливе / зауваження);
- **Те саме для Gushka:** назви й теги оголошень Etsy (66 із 109 активних товарів без жодного тега) — спільний
  механізм підказок, який використовує вже готовий редактор «було → стане» (ADR-0019).

Правило те саме: пропозиції — гіпотези, доки немає даних; людина обирає й редагує, Adelie нічого не публікує сама.

## 4.2. Дослідження за нішами, а не за товарами (рішення власника, 2026-11-11)

Зовнішні дані збираємо **по нішах** (пул ключових слів і ринок: «килими з вовни», «повстяні тапочки»; для моду —
«ETS2 карти», «ATS моди»), а не по кожному товару чи публікації. Ніш мало (5–15 на проєкт), їх задає власник
(або Adelie пропонує, власник підтверджує).

- **Дані по ніші, раз на період (кеш):** теги й назви топових оголошень Etsy за ключовими словами ніші (частота) і діапазон
  цін; Pinterest Trends (зростання, сезонність); за потреби Google Trends через SerpApi; власні агреговані результати по ніші
  (перегляди, «улюблене», продажі товарів ніші).
- **Підказки для товару/публікації** беруться з пулу ніші: AI підбирає слова під атрибути (матеріал, колір, призначення),
  правила платформи (Etsy: 13 тегів по 20 символів, довжина назви) перевіряються детерміновано. **Окремих зовнішніх
  запитів на товар немає.**
- **Бюджет запитів:** орієнтовно 8 ніш × ~6 ключових запитів ≈ 50 запитів на оновлення; раз на місяць це ≈ 50 із 250
  безкоштовних запитів SerpApi (Etsy API безкоштовний у межах 5 000/добу, Pinterest Trends — 60/хв). Запити
  витрачаються на ніші, не на товари.
- **Сутність `ResearchNiche`** (проєкт, назва, ключові слова, ринок і мова, дата оновлення, кеш результатів) і зв'язок
  товару/публікації з нішею (за категорією — у Gushka 13 категорій сайту й таксономія Etsy — або вручну; товар може бути
  у кількох нішах). Збігається з «Niche-based Discovery» з [pebble.md](pebble.md), механізм спільний.
- **SerpApi — необов'язкове джерело** за абстракцією (як AI-провайдер): без нього нічого не ламається; кожен виклик
  кешується на дні; підказки з нього маркуються «за даними ринку (Google Trends)». Ризик: скрейпінг Google (позов Google
  проти SerpApi, DMCA-частина відхилена 2026-07-20, але це не вердикт про легальність). Дані Etsy через SerpApi
  не беремо (умови Etsy), лише через офіційний API.

## 5. Дані й джерела

- **Власні (надійні):** Flipper (з UTM), підключені платформи, ручні числа (завантаження/донати).
- **Ринкова розвідка (пізніше, спільно з Pebble):** публічні дані YouTube Data API (схожі моди, частота, перегляди), довідкові
  сторінки; Reddit і Steam Workshop/Nexus — перевірити доступ і умови перед використанням.
- Знання AI без перевірених джерел використовуємо лише як гіпотези, не як факти про ринок.

## 6. Модель даних (ескіз)

- `Strategy` (проєкт, бриф, мова, години на день, статус);
- `Goal` (метрика, цільове значення, дата, база);
- `StrategyChannel` (канал, роль, частота, гіпотеза);
- `CalendarItem` (дата, канал, формат, ідея, чернетка, час, посилання, статус, зв'язок з виміряною публікацією);
- `WeeklyReview` (період, висновки, прийняті зміни);
- `ResearchNiche` (проєкт, назва, ключові слова, ринок/мова, дата оновлення) і `NicheResult` (джерело, дата, агрегати, основа);
- `MetadataSuggestion` (об'єкт — публікація/мод/товар, платформа, варіанти назви, опис, теги, пояснення, якість доказу, прийнято/відхилено);
- `AiRun` (що запитано, провайдер/модель, вхід без секретів і персональних даних, вихід, вартість) — для пояснюваності й обмежень.

## 7. Правила AI

- Абстракція постачальника (`packages/ai`), перший — **OpenAI**; модель налаштовується; ключі лише на сервері.
- Структуровані відповіді (JSON за схемою), валідація перед збереженням; сирий текст нічого не змінює без підтвердження.
- Поріг витрат на проєкт; журнал `AiRun`; у запити не потрапляють токени платформ і персональні дані покупців.
- Усі числа в висновках — з наших даних, AI їх лише формулює; пояснення «чому» обов'язкове.

## 8. Порядок реалізації (пропозиція)

1. **Фундамент вимірювання:** підключення сайту без каталогу (лендінг моду), **Link Builder** (UTM-посилання), події
   «завантаження»/«донат» як цілі Flipper.
2. **Бриф + ціль + чернетка стратегії** (перший виклик AI, перегляд і редагування).
3. **Календар** зі статусами й порадами «що публікувати».
4. **Щотижневий огляд** з порівнянням цілі й факту.
5. Потім: ринкова розвідка (Pebble), підключення YouTube/TikTok (статистика, публікація), сповіщення про завдання.

## 9. Відкриті питання

- Де моду «жити» (Steam Workshop / Nexus / власний сайт) — від цього залежать цілі й спосіб вимірювання завантажень.
- Чи дає Steam Workshop/Nexus автору дані про завантаження через API (перевірити).
- Моделі OpenAI й ціна запитів; ліміт на проєкт.
- Чи потрібне те саме для Gushka (так само: ціль — продажі/трафік, канали — Pinterest/Instagram) — так, механізм спільний.
