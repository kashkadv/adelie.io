# ADR-0011: Контракт адаптера платформ

- **Статус:** прийнято
- **Дата:** 2026-11-06
- **Пов'язані:** ADR-0008 (зберігання метрик), [plans/stage-2-data-model.md](../plans/stage-2-data-model.md)

## Контекст

Adelie збирає дані з кількох платформ (Pinterest першим, далі Instagram, TikTok). У кожної — свій OAuth, свої
назви метрик, статуси даних, ліміти запитів і помилки. Потрібен спільний контракт, щоб синхронізація,
зберігання й інтерфейс не залежали від конкретної платформи.

## Рішення

- **Адаптер — «перекладач» без бази даних.** Отримує готовий токен і повертає нормалізовані дані: акаунт,
  дошки, пости, точки метрик (`providerKey`, дата UTC, значення або `null`, статус даних, оригінальний статус,
  розрізи). Усе інше — **оркестратор синхронізації** у worker: запис у базу, оновлення токенів, `SyncRun`,
  перерахунок `PostMetricsLatest`.
- **Окремий пакет `packages/platforms`** (`@adelie/platforms`) — ним користуються API (OAuth) і worker (синхронізація).
- **Назви метрик — як у платформи** (`IMPRESSION`); переклад у наші ключі робить оркестратор через довідник
  `MetricDefinition` — одне джерело правди.
- **Посторінкова видача** (`AsyncIterable`) для пінів/дошок: не тримаємо тисячі записів у пам'яті, після ліміту
  продовжуємо з того ж місця.
- **Спільний HTTP-клієнт:** ліміти запитів за заголовками `x-ratelimit-*` окремо для кожного кошика
  (читання / аналітика), повтори з наростаючою паузою, тайм-аути, запис сирих відповідей у `SyncPayload` через
  колбек (лише тіло, без заголовків запиту). Одночасно — не більше однієї синхронізації на підключення.
- **Типізовані помилки:** `TOKEN_EXPIRED` (оновити токен і повторити), `REAUTH_REQUIRED` (підключення →
  «потрібна повторна авторизація»), `RATE_LIMITED` (почекати й продовжити), `TRANSIENT` (повтор),
  `NOT_AVAILABLE` (пропустити крок, `SyncRun` = PARTIAL), `INVALID` (помилка коду, FAILED).
- **Токени** розшифровує й оновлює оркестратор (`@adelie/shared/crypto`); адаптер їх не логує й не зберігає.
- **Сповіщення про проблеми з підключенням** — поки лише в застосунку: позначка на акаунті в «Акаунтах» і банер
  «Перепідключіть …» на «Огляді». **Налаштування сповіщень** (пошта тощо) — пізніше, окремо.

## Альтернативи

- **Адаптер пише в базу сам** — менше коду, але важко тестувати й неможливо перерахувати дані із сирих відповідей.
- **Адаптер повертає наші ключі метрик** — маппінг розмазаний по адаптерах і дублює довідник.
- **Адаптери всередині worker** — API для OAuth довелося б тягнути код worker або дублювати.

## Наслідки

- Адаптери тестуються на записаних справжніх відповідях API (фікстури), без мережі й бази.
- Деталі формату Pinterest, не підтверджені на реальних даних (`pin_metrics`, розбивка `split_field`), позначені
  в коді й перевіряються на PoC 2 (акаунт Gushka).
