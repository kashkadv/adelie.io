# ADR-0024: Модуль «План просування»: AI-помічник за даними, постачальник OpenAI

- **Статус:** запропоновано (чекає підтвердження власника)
- **Дата:** 2026-11-11
- **Пов'язані:** [specs/promotion-strategy.md](../specs/promotion-strategy.md), ADR-0022 (Flipper, Link Builder), [specs/pebble.md](../specs/pebble.md)

## Контекст

Власник хоче, щоб Adelie допомагала будувати стратегію просування для двох проєктів: Gushka і безкоштовного моду для
ETS2/ATS (поки без каналів і аудиторії; ціль — завантаження, донати за бажанням). Потрібні календар публікацій і
поради, що публікувати; ресурс — 1–2 години щодня. Власник погодився на AI-генерацію з перевіркою людиною й
обрав OpenAI як постачальника.

## Рішення

1. **Модуль «План просування» на проєкт:** бриф → ціль → стратегія → календар → щотижневий огляд (цикл у специфікації).
2. **AI формулює, дані вирішують.** Пропозиції (ідеї, канали, гіпотези) генерує LLM за структурою; цифри й висновки
   щодо результатів беруться лише з наших даних (Flipper, платформи, ручні числа). Кожна порада має пояснення й
   позначку якості доказу (гіпотеза / за даними ринку / за вашими результатами).
3. **Постачальник — OpenAI, за абстракцією** (`packages/ai`): модель, ключ і ліміти — налаштування сервера; заміна
   чи додавання постачальника не торкається решти коду.
4. **Людина підтверджує:** AI нічого не публікує й не змінює без явної дії користувача; чернетки редагуються.
5. **Журнал запитів `AiRun`:** що, яка модель, скільки коштувало; **ліміт витрат на проєкт**; у запити не потрапляють
   токени платформ чи персональні дані покупців.
6. **Метадані для знаходження** (назви, описи, теги/хештеги) — частина модуля: варіанти з поясненням і детермінованими
   перевірками довжини, лімітів і дублів; для Gushka — той самий механізм для назв і тегів Etsy.
7. **Дослідження ринку — по нішах, не по товарах** (5–15 ніш на проєкт, кеш результатів, оновлення раз на період):
   підказки для товару й публікації беруться з пулу ніші без окремих зовнішніх запитів; зовнішні провайдери даних (ключові слова й обсяги
   пошуку — кандидат DataForSEO; видача й підказки — Serper або SerpApi) — необов'язкові джерела за абстракцією.
8. **Порядок:** спершу фундамент вимірювання (підключення сайту без каталогу, Link Builder, цілі Flipper), потім
   бриф/стратегія, календар, щотижневий огляд; публікація з Adelie й ринкова розвідка — пізніше.

## Альтернативи

- **Шаблонні поради без AI:** прості й дешеві, але негнучкі та швидко набридають. Лишаємо як запасний шлях для частини
  правил (наприклад, ритм під бюджет часу).
- **Генерація без прив'язки до даних:** швидко, але виходять загальні плани без вимірюваної користі. Відкинуто.
- **Інший постачальник (Anthropic, Google):** технічно можливо; обрано OpenAI за вибором власника, абстракція це не
  блокує.

## Наслідки

- З'являється платна зовнішня залежність і щомісячні витрати на запити; потрібні ліміти й облік.
- Лендінг моду потребує підключення сайту **без каталогу** (зараз «Сайт» = адреса фіду Google Merchant) — окрема дрібна зміна.
- Link Builder стає обов'язковим: без відстежуваних посилань нема чесного вимірювання порад.
- Відкрито: де розповсюджується мод (Steam Workshop / Nexus / власний сайт), чи дає він автору API завантажень, які
  моделі й які ліміти витрат.
