# ADR-0020: Функції підключення й «Оновити доступ»

- **Статус:** прийнято
- **Дата:** 2026-11-08

## Контекст

Нові функції Adelie потребують нових дозволів платформи (перша — «Аудиторія» Pinterest: `ads:read`).
Підключення, зроблені раніше, цих дозволів не мають. Платформи самі про це не повідомляють. Видаляти й
підключати акаунт заново — погано: це лякає й виглядає як втрата даних.

## Рішення

- **Реєстр функцій** (`packages/platforms/src/features.ts`): для кожної платформи — функції та їхні дозволи
  (`core` — обов'язкова; інші — необов'язкові). Вхід завжди просить дозволи всіх функцій.
- **Що бракує** — порівняння збережених `scopes` підключення з реєстром (`missingFeatures`); API віддає це в
  списку підключень.
- **«Оновити доступ»** — повторна згода для **того самого акаунта**: підключення оновлюється на місці
  (токени, дозволи), уся історія лишається. У «Підключеннях» — бурштиновий «!» з поясненням і пункт меню «⋯»;
  на самій функції (напр. «Аудиторія» на «Огляді») — пояснення з кнопкою замість порожнечі.
- Синхронізація не пробує функцію без дозволу (не робить синхронізацію «частковою» через це).
- Необов'язкові функції лише підказують, без банерів.

## Альтернативи

- Від'єднати й підключити заново — зайві кроки, страх втратити історію.
- Тихо пропускати функції без дозволу — людина не дізнається, що дані можна отримати.

## Наслідки

- Нова функція з новим дозволом = запис у реєстрі; індикатор і «Оновити доступ» з'являються самі.
- Для Instagram новий дозвіл спершу додається в конфігурацію входу в кабінеті Meta.
- Якщо платформа не приймає новий дозвіл для застосунку (рівень доступу), вхід поверне помилку — тоді дозвіл
  треба прибрати з реєстру або отримати доступ у платформи.
