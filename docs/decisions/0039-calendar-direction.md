# ADR-0039: Напрям у записах календаря; фокус фільтрує картки

- **Статус:** прийнято
- **Дата:** 2026-11-24
- **Пов'язані:** [ADR-0028](0028-content-calendar.md), [ADR-0030](0030-brief-directions-week-focus.md),
  [ADR-0037](0037-direction-hits.md)

## Контекст

Фокус тижня (ADR-0030) лише вибирав, для якого напряму AI пропонує ідеї; записи календаря про напрям нічого не знали.
При двох напрямах («Світ» і «Україна») картки змішувались, а при «Усі» AI міг змішати аудиторії в одній ідеї.

## Рішення

1. **`calendar_item.direction`** — id напряму з брифу (текст; без напряму — `null`). Задається у вікні запису (поле
   «Напрям», коли напрямів кілька; за замовчуванням — напрям фокусу) і AI-ідеєю. API перевіряє, що це напрям брифу.
2. **Фокус фільтрує картки:** під фокусом напряму видно лише його записи, ідеї й пропозиції; записи без напряму — лише під «Усі»
   (при одному напрямі фільтра немає); «Усі» — усе.
   Хвилини дня рахують усі записи (це час власника), показані чи ні.
3. **Картка показує напрям** (після формату), коли напрямів кілька.
4. **AI при «Усі»:** кожна ідея обов'язково має напрям; канал — з каналів цього напряму (інакше ідея відкидається);
   ідеї розподіляються між напрямами, починаючи з тих, де на тиждень менше запланованого (`plannedThisWeek`); хіт — лише
   для ідеї свого напряму. Для найсильніших ідей рекомендовано фокус на одному напрямі. Напрямів не більше 5.

## Наслідки

- Міграція: одна необов'язкова колонка; наявні записи без напряму видно лише під «Усі» (їм можна вказати напрям у вікні запису).
- Якість ідей при «Усі» нижча, ніж при вузькому фокусі: один запит ділиться на всі напрями.
