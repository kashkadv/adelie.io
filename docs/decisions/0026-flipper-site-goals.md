# ADR-0026: Flipper — тип сайту, цілі й воронка як налаштування

- **Статус:** прийнято
- **Дата:** 2026-11-12
- **Пов'язані:** [ADR-0022](0022-flipper-tracker.md), [specs/promotion-strategy.md](../specs/promotion-strategy.md)

## Контекст

Кабінет Flipper був зашитий під інтернет-магазин: плитки й воронка «Категорія → Товар → Кошик → Оформлення → Покупка»,
вкладка «Оформлення» в кожного сайту. Для лендінгу (мод, Product Factory) це порожнеча, а важливого — «натиснув
Завантажити», «перейшов на донат» — немає. Різні сайти мають різні «успіхи»; додавати типи треба, нічого не ламаючи.

## Рішення

1. **Тип сайту — шаблон із реєстру** (`apps/api/src/flipper/site-kinds.ts`): поки **Магазин** (`store`) і **Лендінг**
   (`landing`). Тип задає стартові цілі й воронку та які вкладки мають сенс («Оформлення», «Товари» — лише магазин).
   Новий тип — новий запис у реєстрі; наявні сайти не змінюються. Невідомий тип читається як магазин.
2. **Цілі (конверсії) — налаштування сайту**, без змін коду сайту:
   - **подія** — назва події (`Purchase`, власні `flipper.track('Download')`);
   - **сторінка** — шаблон шляху з `*` (`/thanks`, `/download/*`) для `PageView`;
   - **перехід на інший сайт** — `OutboundClick` на хост (+ необов'язково початок шляху): `nexusmods.com`, `ko-fi.com`.
   Цінність — з поля `value` події (покупка). Клік по CSS-селектору — не зараз.
3. **Воронка — свої кроки** з подій і цілей (впорядкований список).
4. **Рахується під час перегляду**, не під час прийому: сирі події зберігаються як є, тож змінене чи нове правило
   **перераховує всю історію**.
5. Зберігання — поля `tracked_site.kind`, `goals` і `funnel` (JSON, перевіряється API); `funnel = null` — воронка типу.
6. Кабінет будується з налаштувань: плитки — цілі; «Джерела» — кроки воронки й цілі за каналами; вкладки — за типом.

## Альтернативи

- **Окремі таблиці для цілей і кроків** — більше міграцій і з'єднань; налаштування сайту маленькі й читаються разом.
- **Позначати цілі під час прийому подій** — швидші запити, але зміна правила не діє на минуле.
- **Без типів, лише ручне налаштування** — кожен новий сайт починався б з порожнечі.

## Наслідки

- Наявні сайти отримують тип «Магазин» і ціль «Покупка» — кабінет Gushka виглядає як раніше.
- Лендінг мода: цілі «Завантаження» (перехід на Workshop/Nexus) і «Донат» (Ko-fi тощо) — без змін коду сторінки.
- Link Builder пізніше показуватиме по кожному посиланню не лише переходи, а й досягнуті цілі.
- Запити з правилами — сирий SQL з параметрами; правила валідуються, шаблони шляхів перетворюються на регулярні вирази
  без даних користувача в SQL.
