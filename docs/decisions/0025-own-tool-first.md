# ADR-0025: Adelie — власний інструмент на цьому етапі

- **Статус:** прийнято (2026-11-13)
- **Дата:** 2026-11-11
- **Пов'язані:** [specs/promotion-strategy.md](../specs/promotion-strategy.md), [specs/product-factory.md](../specs/product-factory.md),
  ADR-0019, ADR-0023, ADR-0024

## Контекст

Власник будує Adelie для себе. Є три проєкти, на яких платформа перевіряється: **Gushka** (вироби, Etsy/сайти), **мод для
ETS2/ATS** (безкоштовний, донати) і **Product Factory** (цифрові продукти для Etsy, задум). Власник не хоче вкладати весь
час в один продукт: він диверсифікує, а платформа має довести користь, дав вимірні покращення хоча б в одному з них.
Продавати платформу іншим зараз не планується: якщо інструмент потужний, власник користується ним сам.

## Рішення

1. **Мета етапу — власний інструмент.** Мірило успіху: чи економить він час власника і чи дає вимірний результат у
   проєктах. Продаж, тарифи й зовнішні клієнти — не ціль цього етапу.
2. **Відкладаємо (не видаляємо):** сторінку команди й керування доступами колег; режим для зовнішніх клієнтів
   (Business Verification і Advanced access у Meta, Etsy Commercial Access, App Review для сторонніх); біллінг і тарифи;
   онбординг; `staging`/production для зовнішніх користувачів (dev лишається «production» власника).
3. **Пріоритет — глибина й автоматизація для трьох проєктів:** сайт без каталогу й Link Builder, цілі Flipper, ядро
   «Дослідження ніш», підказки тегів/назв/описів, календар публікацій, далі інтеграції в порядку, який обере власник
   (GA4, Merchant Center, TikTok, YouTube, Threads).
4. **Що лишається обов'язковим:** конфіденційність відвідувачів Flipper (згода, політика); безпека токенів і секретів;
   тести й CI; **резервні копії бази** — тепер важливіші (раніше «бекапів немає» було свідомо відкладено, див. `status.md`),
   бо в базі робочі дані власника; історія старша за 90 днів існує лише в нашій базі.
5. **Обмеження API навіть для власного використання:** публікація через TikTok API і YouTube Data API — приватна, доки
   застосунок не пройде аудит (він вимагає застосунку «для широкої аудиторії»); запис пінів Pinterest вимагає Standard
   access. Тому **автоматична публікація не гарантована ціль**: планувати чернетки й приватні пости, публічну дію
   робить власник у самій платформі, поки доступ не отримано.
6. **Перевірка платформи — три експерименти** з сигналом успіху, обмеженим часом і щомісячним переглядом (продовжити /
   змінити / зупинити):

   | Проєкт | Що робить Adelie | Сигнал успіху | Коли дивитись |
   |---|---|---|---|
   | Gushka | підказки тегів і назв для товарів без тегів | перегляди й «улюблене» у змінених товарів ростуть порівняно з незміненими (журнал змін є) | через 4–6 тижнів |
   | Мод | план, календар, відстежувані посилання | переходи на завантаження й їх конверсія ростуть за каналами; перший донат | через 6–8 тижнів |
   | Product Factory | пошук ніші, чернетки оголошень | перша продажа цифрового продукту, далі повторювані | через 6–8 тижнів після першого оголошення |

   Ліміт часу: мод — 1–2 год на день (як визначив власник); Product Factory до перевірки правил Etsy — лише підготовка.
7. **Опціональність:** багатокористувацька структура (workspace, проєкти, ролі) лишається; нових зусиль на неї не витрачаємо.
   Якщо інструмент виявиться потужним, його можна відкрити іншим і повернути відкладене. Для цього знадобляться ще
   3–5 незалежних користувачів і розмови з ними: власні результати доводять корисність власнику, але не готовність інших платити.
8. **Перегляд рішення** — приблизно через 3 місяці (початок 2027-02) за результатами експериментів.

## Альтернативи

- **Будувати одразу як продукт (SaaS):** більше вимог (верифікації, юридичне, підтримка, онбординг), довше до першої
  користі; відкинуто на цьому етапі.
- **Вкласти весь час в один проєкт:** простіше, але власник свідомо диверсифікує; три експерименти дають більше сигналів.
- **Не мати критеріїв, дивитись «на відчуття»:** відкинуто: без заздалегідь заданого сигналу легко підганяти результат.

## Наслідки

- Менший обсяг: відкладене в п. 2 не розробляється, поки рішення не переглянуто.
- Резервні копії бази стають завданням з вищим пріоритетом.
- Платформа з'являється у відповідь на потребу експерименту: для моду й Product Factory спершу мінімум (календар, таблиця,
  UTM-посилання), автоматизація після підтвердження потреби.
- У `status.md` пункти про сторінку команди й Etsy Commercial Access позначено як відкладені цим ADR.
