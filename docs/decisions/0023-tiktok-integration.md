# ADR-0023: Інтеграція TikTok — статистика, публікація, редагування

- **Статус:** запропоновано (чекає підтвердження власника)
- **Дата:** 2026-11-11
- **Пов'язані:** ADR-0004 (порядок платформ), ADR-0011 (адаптер платформ), ADR-0017 (щоденні метрики з різниці
  знімків), ADR-0019 (рівні доступу підключень)

## Контекст

Власник хоче підключити TikTok: **статистику**, а також **публікацію й редагування** контенту. TikTok — третя
платформа після Pinterest і Instagram (ADR-0004: «пізніше»). Дослідження публічної документації (2026-11-11);
пункти, не підтверджені офіційними сторінками, позначено «не підтверджено».

Що дозволяє API:

- **Login Kit + Display API** (TikTok for Developers): профіль акаунта й статистика (`user.info.basic`,
  `user.info.profile`, `user.info.stats` — підписники, лайки, кількість відео), список відео з показниками
  (`video.list` — перегляди, лайки, коментарі, поширення). Це **підсумки за весь час**, не по днях. Працює з
  будь-яким (також особистим) акаунтом.
- **Content Posting API:** пряма публікація (`video.publish`) і чернетка в застосунку TikTok (`video.upload`).
  Поки застосунок **не пройшов окремий аудит** публікації, пости можуть бути лише **приватними**, а акаунтів — не
  більше 5 на добу. Правила публікації (Content Sharing Guidelines) вимагають конкретного інтерфейсу: дані автора,
  вибір приватності, позначки комерційного контенту, жодних прихованих значень за замовчуванням.
- **Редагування опублікованого — немає.** Після прийняття поста API відхиляє зміну підпису чи приватності (статус
  «опубліковано»); видалення через API, за сторонніми джерелами, теж недоступне (не підтверджено офіційно).
  Змінити можна лише до публікації.
- **Глибша аналітика** (демографія, джерела переглядів, добові ряди) — окремо, в **Accounts API** (Organic API
  TikTok for Business): лише для Business-акаунтів, окремий портал і доступ; демографія — від ~100 підписників
  (не підтверджено офіційно, умови доступу треба перевірити в порталі).
- Перевірка застосунку (App Review) ручна: від кількох днів до двох тижнів; потрібні політика конфіденційності й
  умови на сайті (є: `adelie.space/privacy`, `/terms`), пояснення для кожного дозволу, демонстрація в sandbox.

## Рішення

1. **Поетапно, як Instagram.** TikTok для читання — окремий етап від публікації.
   - **Етап 1 — читання:** Login Kit + Display API. Адаптер за ADR-0011 (`packages/platforms/src/tiktok`): профіль,
     відео зі статистикою, знімки акаунта. Щоденну динаміку відео рахуємо з різниці знімків (ADR-0017), як для
     Instagram; історії до підключення немає. Метрики — як у платформи (`view_count`, `like_count`,
     `comment_count`, `share_count`), переклад у наші ключі — через довідник `MetricDefinition`.
   - **Етап 2 — публікація:** спочатку **чернетки** (`video.upload`), потім пряма публікація (`video.publish`)
     після аудиту. Окрема форма публікації за правилами TikTok. Потрібне **сховище відеофайлів** (зараз його немає;
     окремий ADR перед реалізацією: куди, скільки зберігати, як віддавати TikTok — завантаження частинами
     `FILE_UPLOAD` без верифікації домену, або `PULL_FROM_URL` з верифікованим доменом).
   - **Етап 3 — глибша аналітика** (Accounts API) — за потреби й залежно від доступу; поки не плануємо.
2. **Рівні доступу за ADR-0019:** «Лише читання» (за замовчуванням: `user.info.*`, `video.list`) і «Повний доступ»
   (додатково `video.upload`, згодом `video.publish`). Змінити — повторна згода («⋯» → «Змінити доступ»). Ніколи —
   дії, яких користувач не зробив сам.
3. **«Редагування» = лише до публікації.** У Adelie можна змінювати підпис, обкладинку, час і налаштування чернетки
   чи запланованого поста; після публікації в інтерфейсі пояснюємо, що зміни лише в самому TikTok.
4. **Заявку на публікацію подаємо паралельно з етапом 1**, бо перевірка найдовша. Усі дозволи (включно з
   `video.publish`) — одним застосунком, але до аудиту публікація лише приватна, про що Adelie має чітко попереджати.
5. **Токени:** access-токен короткий (≈ доба), refresh — довгий; оновлення заздалегідь у worker, як для інших
   платформ (`TOKEN_EXPIRED` → оновити, `REAUTH_REQUIRED` → «потрібна повторна авторизація»). Ключ застосунку
   (`client_key`/`client_secret`) — лише на сервері.
6. **Рівень Display vs Business:** Display API використовуємо без вимоги Business-акаунта; якщо в Gushka особистий
   акаунт — етап 1 однаково працює.

## Альтернативи

- **Одразу публікація й аналітика через Business/Accounts API:** глибші дані, але доступ ручний і невідомий у
  строках, потрібен Business-акаунт; затримує навіть просте читання.
- **Редагування опублікованих через «видалити й створити заново»:** API видалення, ймовірно, немає, а втрата
  переглядів і коментарів неприйнятна. Відкинуто.
- **Публікація лише через чернетки назавжди:** простіше за аудит і правила інтерфейсу, але користувач має завершити
  пост у застосунку TikTok. Лишається запасним варіантом, якщо аудит не вдасться.
- **Сторонній агрегатор (Ayrshare, Late тощо):** швидший старт, але залежність, плата за користувача й менше
  контролю над даними. Відкинуто для основного шляху.

## Наслідки

- Потрібен акаунт TikTok for Developers, застосунок із продуктами Login Kit, Display API, Content Posting API;
  redirect URI (dev: `https://dev-api.adelie.space/social/tiktok/callback`); ключі лише на сервері. Деталі кроків
  створення застосунку — у `docs/integrations/tiktok.md` (створити разом з етапом 1).
- Privacy policy доповнити (TikTok, які дані читаємо, запис лише за явною дією користувача, примітка про торговельну
  марку TikTok) — як для Etsy.
- До аудиту публікації користувачі бачитимуть лише приватні пости: це треба пояснювати в інтерфейсі.
- Публікація додає нову підсистему (сховище відео, чернетки, планувальник, форма за правилами TikTok) — окремі
  ADR і план перед етапом 2.
- Відкрито: чи є в Gushka акаунт TikTok і якого типу (особистий / Business; у ADR-0004 було «акаунта немає»);
  звідки брати відео для публікації (завантаження в Adelie чи інше джерело); перевірити в порталі актуальні
  ліміти запитів (у сторонніх джерелах ~6/хв на користувача, суперечливо) і поточні умови аудиту.
