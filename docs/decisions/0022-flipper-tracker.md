# ADR-0022: Flipper — трекер подій сайту

- **Статус:** прийнято (2026-11-10, власник)
- **Дата:** 2026-11-10

## Контекст

[specs/tracker.md](../specs/tracker.md) описує модуль «Adelie Tracker»: один скрипт на сайті, єдиний потік подій,
джерела трафіку, пізніше атрибуція. Перший сценарій — сайти Gushka (`gushka.ua`, `gushka.world`; Next.js, повний
контроль над кодом), які вже підключені як сайти з фідами ([ADR-0021](0021-website-catalog-feeds.md)). Потрібен
спосіб «легко підключити через CDN» і гайд для подій: перегляд категорії, товару, додавання в кошик, оформлення.

## Рішення

1. **Назва — Flipper** (крильце-плавець пінгвіна). Скрипт `flipper.js`, глобальний об'єкт `window.flipper`, cookie
   з префіксом `_fl_`, ідентифікатор сайту `fl_…`.
2. **Сайт Flipper = підключений сайт** (`tracked_site`, один на акаунт-сайт). Кожен домен має **власний** ідентифікатор
   і власні звіти (ринки, валюти); відвідувач, що переходить між власними доменами, переноситься опційним
   **лінкером** `data-link-domains` (лише за згодою). `site_id` — не секрет: захист приймача — суворий парсер, ліміти,
   allowlist хостів (допоміжно), без збереження IP.
3. **Скрипт** (`packages/tracker`, esbuild → один файл ≈ 7 КБ, без залежностей) віддає API: `GET /flipper.js`
   (кеш 5 хв). Адреси на першому етапі — наявний `dev-api.adelie.space` (`/flipper.js`, `/collect`); окремі
   `cdn.` / `events.adelie.space` — при виході на production. Скрипт ніколи не кидає помилок у сторінку,
   асинхронний, надсилає пачками через `sendBeacon`.
4. **Згода: анонімно до згоди.** Без згоди — жодного cookie чи сховища в браузері, без visitor/session ID; рахуються
   перегляди й події. Анонімні **унікальні за добу** — серверний хеш (сайт + браузер + адреса запиту під сіллю, що
   змінюється щодня; адреса й браузер не зберігаються) — `dailyId`, не зв'язує дні. Після `flipper.consent('granted')`:
   постійний `visitor_id` (cookie `_fl_v`, 400 днів), сеанс (`_fl_s`, 30 хв), атрибуція сеансу (`_fl_a`), воронка.
   Do Not Track і Global Privacy Control — нічого не надсилається. З адрес лишаються лише utm-параметри й click id
   (gclid, fbclid, ttclid, epik, msclkid) та дозволені сайтом (`data-allow-params`).
   **Рішення для Gushka (2026-11-10):** `gushka.ua` — повний режим одразу (`data-consent="granted"`, аудиторія
   переважно українська, банера немає); `gushka.world` — завжди анонімний (покупці з ЄС), доки не буде банера згоди.
   Відповідальність за підставу обробки — на власнику сайту.
5. **Події.** Автоматично: `PageView` (з SPA-переходами через History API), `OutboundClick`. Магазин:
   `ViewCategory`, `ProductView`, `AddToCart`, `BeginCheckout`, `Purchase` (клієнтська подія оплати з `transaction_id`; серверну додамо пізніше) (стандартні властивості: `item_id` — артикул = `g:id`,
   `item_name`, `price`, `currency`, `quantity`, `value`, `items`). `Purchase` — **лише з сервера** (окремий етап).
   Способи підключення: JS API і `data-flipper-*` (зроблено); автовиявлення (GA4 `dataLayer`, JSON-LD `Product`) і
   правила з кабінету (шаблони адрес, CSS-селектори) — наступні кроки.
6. **Джерело визначається на сервері** (`classifyVisit`): `source`, `medium`, `campaign`, `content`, `term`,
   `clickIdType` і `channel` зберігаються окремо; канали за правилами GA4 (Organic/Paid Search, Organic/Paid Social,
   Email, Affiliate, Display, Referral, Direct, Other). Пріоритет: utm → click id → referrer → direct.
7. **Сховище:** Postgres (`website_event`), унікальність `(siteId, eventId)` — повторне надсилання не дублює;
   `occurredAt` окремо від `receivedAt`; боти позначаються (`isBot`) і не показуються; зберігання **425 днів**
   (щоденне прибирання у worker).
8. **Кабінет:** розділ «Сайт → Flipper»: увімкнення, код встановлення, статус («остання подія»), показники за 7/30/90
   днів, унікальні за добу, воронка (лише зі згодою), канали, топ товарів, події наживо, гайд.

## Альтернативи

- **Один сайт Flipper на обидва домени.** Відкинуто: різні ринки й валюти, різні фіди. Спільний звіт — пізніше.
- **Cookie без згоди.** Відкинуто: ризик для клієнтів з ЄС.
- **Нічого до згоди.** Відкинуто: даних не буде зовсім, поки сайт не підключить банер.
- **Імітація Googlebot/ClaudeBot для SEO-перевірки** — відкинуто (чужа ідентичність); використовується `adelie-bot`.

## Наслідки

- Публічний приймач на домашньому dev-сервері — достатньо для Gushka; для зовнішніх клієнтів потрібні окремі
  хости, CDN і, ймовірно, окреме сховище подій (ClickHouse) при великих обсягах.
- Анонімні «унікальні за добу» — оцінка; у звітах це підписано. Воронка й повернення — лише зі згодою.
- Потрібні Link Builder (узгоджені utm), правила з кабінету, автовиявлення та серверний `Purchase` — наступні кроки.
