# ADR-0003: Автентифікація

- **Статус:** запропоновано
- **Дата:** 2026-11-05

## Контекст

Потрібні реєстрація/логін, сесії, у перспективі — workspaces з ролями та інвайтами.
Вимога: готове безкоштовне рішення без проблем із ліцензіями та правами на дані.

## Пропозиція

**Better Auth** (ліцензія MIT, open source, self-hosted).

- Безкоштовно, без лімітів на кількість користувачів — працює в нашому коді.
- Користувачі й сесії зберігаються в нашому PostgreSQL (є Prisma-адаптер) —
  немає vendor lock-in, дані повністю наші.
- Email/пароль, OAuth-логін (Google тощо), 2FA — через плагіни.
- Плагін organizations (організації, учасники, ролі, інвайти) — можливо,
  підійде як основа для workspaces. Перевірити, чи не конфліктує з нашою
  моделлю ролей Owner/Admin/Analyst/Viewer.
- Інтеграція з NestJS — перевірити при створенні скелета (офіційна підтримка
  чи монтування handler'а вручну).

Важливо: це логін користувачів **в Adelie**. OAuth-підключення соцмереж
(TikTok, Pinterest, Instagram) — окрема власна логіка adapters, не через auth-бібліотеку.

## Альтернативи

- **Clerk** — хостований, якісний, але безкоштовний лише до ліміту,
  користувачі живуть у сторонньому сервісі (lock-in).
- **Auth.js (NextAuth)** — прив'язаний до Next.js, а сесії потрібні в NestJS API;
  проєкт зараз підтримується командою Better Auth.
- **Власна реалізація** — повний контроль, але багато коду з ризиками безпеки.

## Наслідки

- Таблиці auth генеруються Better Auth і живуть у `packages/db` поряд із нашою схемою.
- Потрібно перевірити версію та NestJS-інтеграцію перед прийняттям.
