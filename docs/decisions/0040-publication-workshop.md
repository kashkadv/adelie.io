# ADR-0040: Майстерня публікацій — візуал і текст у записі календаря

- **Статус:** прийнято (2026-11-25; можливі правки згодом)
- **Дата:** 2026-11-24
- **Пов'язані:** [ADR-0028](0028-content-calendar.md), [ADR-0027](0027-link-builder.md),
  [ADR-0029](0029-ai-brief-and-ideas.md), [ADR-0041](0041-gpu-worker-on-demand.md),
  [plans/pin-workshop.md](../plans/pin-workshop.md)

## Контекст

Календар каже, що й коли публікувати, але готові матеріали (картинка піна, текст, посилання) власник робить поза Adelie.
Мета — 20+ публікацій на тиждень (Pinterest-пін 2:3, Instagram-пост 4:5), тож потрібна «майстерня»: з ідеї швидко
отримати готовий набір, який лишається вручну опублікувати (публікація через API недоступна, див. ADR-0025).

## Рішення

1. **Майстерня — режим запису календаря**, а не окрема сутність. Ідея й план — той самий запис `calendar_item`
   (статуси ідея → чернетка → готово → опубліковано → виміряно); перетягування на день лише призначає дату. Усе створене
   в майстерні (візуали, варіанти, текст, посилання) зберігається в записі й видно в його картці в усіх статусах.
2. **Один запис = одна публікація = один канал.** Той самий візуал для іншого каналу — дія «Копія на інший канал»
   (новий запис з тим самим візуалом, іншим шаблоном і текстом).
3. **Потік:** старт (з ідеї / товару / порожньо) → візуал (референси, фото товару з каталогу, дії над ним) → шаблон
   і кадрування під канал → текст каналу від AI (за брифом, напрямом, дослідженням; з лімітами каналу) → мічене
   `go.`-посилання з Link Builder → видача: завантажити PNG, копіювати назву/опис/теги одним кліком, відкрити створення
   піна в Pinterest, поставити дату.
4. **Шаблони — два джерела, один формат.** Рендерер (Satori + resvg, на сервері, self-hosted шрифти проєкту: Inter,
   Onest, Playwrite IT Trad 300) приймає шаблон як дерево шарів із ролями слотів `#photo`, `#title`, `#logo`, `#badge`;
   фрейми 1000×1500 (пін) і 1080×1350 (пост).
   - **Figma** (ручні шаблони): REST API, personal access token лише для читання (зашифрований, як токени підключень);
     «Синхронізувати з Figma» читає дерево шарів, статичні елементи експортує SVG. Малювати треба шрифтами проєкту.
   - **Власні файли шаблонів** (JSON/SVG у репозиторії, версії в git): їх може писати AI — варіанти за стилем і токенами
     ADR-0009 з прев'ю в Adelie, без Figma й авторизації.
   - **AI у Figma** (необов'язково): у сесії з Claude через конектор Figma (потрібна авторизація; що конектор уміє
     створювати — перевірити); REST API Figma лише читає, тож усередині Adelie шаблони в Figma не створюються.
   - AI-генерація шаблонів у самому застосунку («опиши стиль — три варіанти») — після етапу 1, коли формат усталиться.
5. **Пакетні дії від початку** (обсяг 20+ на тиждень): «підготувати збірки для запланованих записів тижня» (AI-текст,
   шаблон за правилом), серія заголовків за одним візуалом, перегляд сіткою прев'ю з «схвалити / відхилити / переробити».
6. **Візуальні дії на GPU** (апскейл, вирізання з фону, новий фон, «без виробу») виконує GPU-воркер за потреби
   ([ADR-0041](0041-gpu-worker-on-demand.md)); без ПК працюють шаблони, кадрування й текст.
7. **Чесність фото:** сам виріб не генерується — лише оточення навколо справжнього фото (вимоги Etsy/Pinterest до
   AI-контенту й очікування покупця). Рубрика «З Гушкою / без Гушки»: пара кадрів зі справжнім виробом / прибраним із сцени.
8. **Етапи:** (1) без GPU: записи з візуалом, Figma-шаблони, текст, посилання, видача, пакетні дії; (2) GPU-воркер;
   (3) рубрика «З Гушкою / без Гушки».
9. **Бібліотека файлів проєкту.** Усі зображення (референси, вихідні фото, згенеровані варіанти, фінальні) — файли
   бібліотеки; записи календаря й товари посилаються на них з роллю (референс / вихідне / варіант / фінальне). Файл має
   походження (завантажено / фото товару з каталогу, кешується при першому використанні / наш допис / чужий пін як
   натхнення — лише посилання й знімок для стилю, не для відтворення), розмір, мітки, хеш (без дублікатів); для
   згенерованого — батьківський файл і рецепт (воркфлоу, параметри). Окремого мудборду проєкту поки немає: питання
   відкрите, повернутись після етапу 1 (мітки й «обране» в бібліотеці покривають потребу).
10. **Звідки приходять референси:** найчастіше власні фото з фотосесій на Google Диску. Етап 1: завантаження
    перетягуванням у браузері (з папки Google Drive for desktop на Mac). Далі — імпорт з Google Диска через Picker (обмежений
    доступ лише до вибраних файлів, без дозволу на весь Диск); обрані файли **копіюються** в бібліотеку, Диск не дзеркалиться.
11. **Зберігання:** HDD на сервері Proxmox (диски ≈ 500 ГБ і ≈ 250 ГБ), підключені до VM `adelie` окремим томом
    (`/srv/adelie-assets`). Оригінали й варіанти — на більшому диску; мініатюри й робочий кеш — на системному диску VM
    (швидше). Резервування: другий диск — щоденна копія оригіналів (rsync), оригінали власних завантажень — також у
    зашифровану копію R2 (як база, [infra/backups.md](../infra/backups.md)); згенеровані варіанти можна відновити, їх копіюють
    не обов'язково. Моніторинг SMART. Віддача файлів — лише через API з автентифікацією.
12. **Очищення після публікації.** Лишаються назавжди: фінальна картинка опублікованого запису, рецепт вибраного
    варіанта й власні оригінали, яких немає на Google Диску. Невибрані варіанти видаляються через 24 години після статусу
    «опубліковано» (короткий запас на передумав); для записів, видалених або не опублікованих, — через 7 днів. Кешовані референси
    (фото товарів, знімки чужих пінів) видаляються, коли на них ніхто не посилається; завантажені референси — лише якщо
    джерело (файл на Google Диску) відоме. Видаляти можна й вручну: будь-який варіант чи референс — одним кліком, а також «Очистити зараз» для запису
    (усе невибране одразу, не чекаючи строку); файл, що використовується в інших записах, видаляється лише з цього запису.
    Захист: «Залишити» на будь-якому файлі, лічильник посилань, показ звільненого
    місця в налаштуваннях.

## Альтернативи

- **Окрема сутність «збірка» на кілька каналів** — відхилено: календар вимірює результат по каналах, один запис на
  публікацію природніший.
- **Власний редактор шаблонів в Adelie** — дорожче в розробці; Figma вже є й дає повну свободу дизайну.
- **Повністю згенеровані AI зображення виробів** — ризик розбіжності з товаром і правил платформ.

## Наслідки

- До запису календаря — поля для візуалів, шаблону, тексту каналу (міграція); таблиця шаблонів Figma й файлів (зображень).
- Розмір зберігання зображень → сховище (об'єктне або диск VM) — вирішити в плані.
- Залежності: Satori + resvg; токен Figma (ліміти запитів залежать від тарифу — перевірити).
- Автоматична позначка «опубліковано» за посиланням і замір результатів працюють без змін.
