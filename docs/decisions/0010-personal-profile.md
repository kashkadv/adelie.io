# ADR-0010: Профіль користувача (персональні налаштування)

- **Статус:** прийнято
- **Дата:** 2026-11-06

## Контекст

Користувачеві потрібні персональні налаштування: ім'я, прізвище, посада, фото, контакти (пошта, телефон,
месенджери) і робочий час — щоб колеги в агенції знали, хто це і як і коли з ним зв'язатися.
Це налаштування людини, а не проєкту чи workspace.

## Рішення

- **Один профіль на людину** для всіх workspace — таблиця `UserProfile` поруч із таблицею Better Auth
  `user` (дані входу й особисті дані не змішуються). Профіль бачить сам користувач і **учасники
  workspace, де він теж є**; усім іншим — нічого (фото віддається з 404).
- **Ім'я й прізвище** — окремі поля; `user.name` (його показує Better Auth) синхронізується як
  «Ім'я Прізвище» і ніколи не стає порожнім. **Посада** — окреме поле.
- **Пошта для входу не змінюється** (і зміна поки не потрібна). **Контактна пошта** — окреме необов'язкове
  поле, може відрізнятися від пошти для входу.
- **Контакти** — фіксований набір: телефон, Telegram, WhatsApp, Viber, LinkedIn. Нормалізуються на сервері:
  телефон → `+` і цифри; Telegram → нік без `@`; LinkedIn → `https://…linkedin.com/…`.
- **Робочий час** — часовий пояс (IANA), робочі дні (ISO: 1 = пн … 7 = нд), один проміжок «з–до».
- **Фото** — у базі (`bytea`): браузер обрізає до квадрата 256×256 (WebP, або JPEG без кодувальника WebP),
  сервер перевіряє тип за сигнатурою байтів і розмір (≤ 150 КБ). Віддається з `GET /users/:id/avatar`
  з перевіркою доступу. Згодом — перенесення в об'єктне сховище (Cloudflare R2) без зміни API.
- **Сторінка «Профіль»** `/me` — з меню аватарки; «Налаштування» в сайдбарі лишаються
  для проєкту й команди. Тема й мова продубльовані на сторінці як особисті вподобання.
- **Privacy policy** доповнено розділом про дані профілю.

## Альтернативи

- **Профіль у кожному workspace окремо** — гнучкіше, але людині довелося б заповнювати його кілька разів.
- **Фото одразу в R2** — зайве налаштування інфраструктури для аватарок, поки користувачів мало.
- **Ресайз на сервері (sharp)** — нативна залежність з install-скриптом; ресайз у браузері простіший.
- **Довільний список контактів** — гнучко, але складніше показувати й перевіряти; фіксований набір покриває
  потреби агенцій в Україні.

## Наслідки

- API: `GET/PATCH /me/profile`, `PUT/DELETE /me/avatar`, `GET /users/:id/avatar`.
- Помилки валідації повертаються кодами (`invalidPhone`, `endBeforeStart`…), інтерфейс перекладає їх.
- Сторінка команди (профілі колег) — пізніше, на тому ж API й правилі видимості.
