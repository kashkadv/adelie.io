# Локальна LLM на робочому ПК (GPU-воркер за потреби)

**Статус:** план перевірки (2026-11-11), нічого не встановлено. Пов'язані: [ADR-0024](../decisions/0024-promotion-strategy-module.md)
(абстракція постачальника AI), [ADR-0025](../decisions/0025-own-tool-first.md), [server-setup.md](server-setup.md).

## Залізо власника

Core i5-12600K (10 ядер), **RTX 3060 Ti (8 ГБ VRAM)**, 32 ГБ RAM; на ПК є Windows і Linux (подвійне завантаження).

## Що реально

- **7–9 млрд параметрів** (стиснення Q4) вміщуються у VRAM повністю й працюють швидко: теги, варіанти назв, описи Etsy
  англійською.
- **~14B** частково на CPU/RAM — повільніше, але можливо. **30B+** — нереально за швидкістю.
- Якість нижча за хмарні моделі на складних таблицях/формулах, довгих структурованих відповідях і українській.

## Рішення (пропозиція)

**Не перетворювати робочий ПК на постійний сервер.** Adelie лишається на VM Proxmox (надійніше, не залежить від роботи/ігор на ПК,
менше шуму й споживання). ПК — **GPU-воркер за потреби**: коли він увімкнений і доступний, Adelie користується локальною
моделлю; інакше автоматично хмарною (за абстракцією з ADR-0024).

## Крок 1 — перевірка якості (години, не дні)

Найпростіше на **Windows**: встановити Ollama (інсталятор з ollama.com), завантажити 1–2 моделі 7–9B з бібліотеки
`ollama.com/library` (сімейства Llama, Qwen, Gemma, Mistral — актуальні назви звірити там), порівняти з хмарною на **реальних
завданнях**: теги й назви оголошень Etsy, описи, ідеї для календаря. Оцінювати за заздалегідь заданими критеріями (точність,
природність англійської, дотримання лімітів: 13 тегів по 20 символів).

## Крок 2 — підключення до Adelie (якщо якість влаштує)

1. Постійний режим краще на **Linux** (Ubuntu): драйвер NVIDIA, Ollama як служба; Windows лишається для роботи.
   Якщо ПК завантажений у Windows, воркер недоступний — це нормально, спрацює запасний хмарний постачальник.
2. Ollama віддає **OpenAI-сумісний API** (`/v1`), тож у Adelie це звичайний постачальник із власною адресою.
3. **Безпека:** Ollama не має автентифікації. **Не відкривати в інтернет.** Слухати лише інтерфейс Tailscale (змінна
   `OLLAMA_HOST` з Tailscale-адресою) або обмежити брандмауером; доступ — лише з VM `adelie` через приватну мережу.
4. Побудити за розкладом/вручну: Wake-on-LAN для масових задач (за потреби).

## Ризики й примітки

- Споживання й шум ПК при роботі 24/7; без ДБЖ відключення світла загрожують даним і перезапусками; тому постійний сервер — не ціль.
- Конфлікт з роботою/іграми за GPU: воркер лише коли ПК вільний.
- Оновлення моделей і драйверів — ваш час.
- Для публічного продукту (не власного) локальні моделі потребують окремого перегляду умов ліцензій конкретної моделі.

## Відкриті питання

- Які моделі й квантизації дадуть прийнятну якість (визначається на кроці 1).
- Чи виправдає масовий обсяг відеокарту з більшою пам'яттю чи сервер із GPU (рішення після кроку 1).
